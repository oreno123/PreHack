# 领域速览侦察（Domain Scout）

## Overview

输入一个陌生领域名，产出一页可交付的中文速览简报，**markdown + HTML 双轨落盘**（md 存档、HTML 给人看）。方法论来自 scout-agent 项目：**拆解（plan）→ 三轮搜索（search）→ 深读（fetch）→ 合成（synthesize）**，在 Claude Code 内直接用自带工具执行。主对话自己搜，不派子代理。

产出定位：**侦察兵的一页报告**——看完知道这个领域的格局、术语、玩家、争议和入口，能和人聊十分钟，知道下一步读什么。不是教材，不是深度研究。

## 与 learn-anything-skill 的分工

- 本 skill：一次性跑完，产出速览简报，回答"这领域是什么样"
- learn-anything-skill：多轮陪练、项目驱动，回答"我要掌握它"

"教我/学 XX"走 learn-anything；"了解一下/什么格局/快速搞懂"走本 skill。简报交付后用户想深入时，建议移交 learn-anything-skill。

## Flow

### 0. 定口径（最多 1 问，能不问就不问）

意图已明确（如"了解 XX 行业的竞争格局"）直接跑。不明确时只问一个最影响方向的问题——**了解这个领域是为了什么？**（写作业 / 跟人聊 / 投资决策 / 求职 / 技术选型 / 纯好奇），用途决定侧重：

- 投资/商业 → 格局 + 数据 + 竞争优先
- 求职 → 产业链 + 公司 + 岗位优先
- 技术 → 概念体系 + 技术栈 + 社区优先

### 1. Plan：拆搜索查询

把领域拆成 6-10 个查询，对着简报模板的空格拆：

- 是什么/定义/边界（中英文各 1 条）
- 格局 / 产业链 / 分层
- 主要玩家 / 公司 / 机构
- 关键数据 / 市场规模（带最新年份，如 "2025"）
- 争议 / 批评 / 瓶颈
- 最近 12 个月动态

**语言策略**：技术、学术、国际性领域以英文查询为主（WebSearch）；政策、消费、本地行业、中文互联网领域以中文为主（web-search-prime MCP，location=cn）。不确定就双语都搜。引擎退化或查不到时用 `site:` 定向搜官方站/维基/行业站。

### 2. Search：三轮搜索

单轮漏检率高，禁止一轮搜完就动笔：

- **R1 全景扫描**：跑完 plan 的查询，建立地图，收集来源 URL 池
- **R2 定向补缺**：对照简报模板逐格检查，缺什么补搜什么（玩家空缺？数据过旧？争议没找到？）
- **R3 数字验证**：准备写进简报的每个关键数字，找第二个独立来源交叉验证；找不到的标"单一来源"

### 3. Fetch：深读核心来源

从 URL 池挑 3-6 个信息密度最高的来源 WebFetch 深读，优先级：行业报告页 / 综述 / 官方数据页 / 高质量长文。目的=拿具体事实、数字、定义，不是扫标题。

### 4. Synthesize：合成简报（双轨输出）

按下方固定模板写，**落盘到 Obsidian 库行业速览夹**（Obsidian 只索引库内文件，直接落库免手动搬；已有同主题简报则更新原文件并保留日期版本记录）：

- `C:\Users\lenovo\Documents\Obsidian Vault\行业速览\<topic>-brief.md` —— 存档版，纯内容，Obsidian 原生索引可双链
- `C:\Users\lenovo\Documents\Obsidian Vault\行业速览\<topic>-brief.html` —— 阅读版，基于 `assets/brief-template.html` 骨架填写

**HTML 规范**（继承用户讲义纪律）：零 CDN、零 JS、全部内联 CSS；浅色严肃风禁花哨；结论卡置顶（左侧色条强调）；表格化呈现格局/玩家/数字；来源双列小字；accent 色按领域气质选（如美妆酒红、能源深绿），只动 `:root` 变量不改结构；打印友好（@media print）。完成后 `start` 弹出 HTML。

**深度要求**（用户 09-08 点名反馈："细点，格局多一些图表"）：

- **概念不点名带过**：领域核心概念（如 BEV/PHEV/EREV、化妆品四大品类）用卡片展开——原理、优缺点、代表玩家，外行读完能复述
- **格局区和玩家区至少各配 2 个图表**，零 JS 纯 CSS 实现（组件全在 `assets/brief-template.html`）：
  - 对比条形图（`.bar-row`）——销量/营收/份额，混口径时用不同色+图注说明
  - 发散条形图（`.div-row`）——盈亏/增速正负对比，中轴线
  - 堆叠结构条（`.stack`）——品类/结构占比，无来源的拆分标[判断]
  - 热力矩阵（`.heat`）——玩家×能力定性评估，四档色块+图例，每个格子可溯源或标[判断]，未查到用灰格
  - 链条图（`.chain`）——产业链上游→下游流程
- 图表每个数据点带来源编号；口径不同的数据不混画一张图，必须画就分色+注明
- 没有来源的数不画：缺数列（如历年渗透率）就只画已验证的点，不补伪数据

交付时在对话里给一句话结论 + 两个文件路径，并附 2-4 个"值得继续深挖的方向"供用户选。

## 简报模板（固定结构，结论先行）

```markdown
# <领域> 速览
> 一句话结论：<这个领域是什么 + 当前最关键的一个事实>（YYYY-MM-DD 侦察，基于 N 个来源）

## 1. 这是什么
2-4 句：定义、解决什么问题、和相邻领域的边界

## 2. 格局地图
子领域 / 产业链分层 / 流派，用列表或表

## 3. 关键概念
| 术语 | 一句话解释 |（6-12 个，让人能听懂行话）

## 4. 主要玩家
| 玩家 | 是谁 | 干什么的 / 地位 |（公司 / 机构 / 人物 / 标准组织）

## 5. 关键数字
| 指标 | 数值（年份） | 来源 [n] |
每个数字必须有年份和出处；暂估标"暂估"；查不到写"未查到"，不编。

## 6. 争议与分歧
支持方 vs 质疑方各说了什么；领域内没有共识的问题

## 7. 入口材料
如果要深入：读什么（综述/教材/报告/社区/期刊），每条一句话说明为什么读它

## 来源
[n] URL —— 类型（官方/媒体/研究/社区）+ 发布时间
```

正文不堆链接，用 [n] 编号引用，URL 集中在来源区。

## 纪律红线

- **主对话自己搜**，不派子代理
- **每个关键数字带年份 + 来源**；暂估标"暂估"，未查到写"未查到"，禁止编造或假精确
- **区分事实与判断**：来自来源的写事实并给出处编号；自己综合的推断明确标"判断"
- **时效**：优先 24 个月内的来源；用旧数据必须标年份
- **来源 ≥ 8 个**才合成；不足就继续搜，或如实说明覆盖缺口在哪
- 结论先行：一句话结论永远置顶，让不读正文的人 10 秒拿到答案
