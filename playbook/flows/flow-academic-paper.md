# Flow · UC14 学术论文型

**判型特征**：会议/期刊 deadline 驱动，多轮评审 + rebuttal，交付 = 论文 + 补实验。周期月级。

**核心律**：实验完整性与故事自洽优先于指标极致；提交不是终点，rebuttal 是第二轮比赛。

## 阶段权重

| 阶段 | 权重 | 裁剪规则 |
|---|---|---|
| 0 情报 | 换成 venue 情报 | deadline（含 abstract/全文双档）、主题契合、页数模板、匿名规则、AI 披露政策 |
| 1 选题 | = 研究问题 | delta 一句话说清："相比 X，本文用 Y 解决了 Z" |
| 2 spike | = 最小可行实验 | 核心 claim 的最小验证；跑不通换 claim，别硬写 |
| 3 设计 | = 论文骨架 | Intro 起手式：gap→问题→方法→贡献；图表清单先行 |
| 4 构建 | 实验+写作并行 | 图表驱动写作：每张图对应一段论述；消融实验铺开 |
| 5 交付物 | 论文打磨 | 格式/匿名/引用逐条核验（引文必须真实查过原文，禁二手转述） |
| 6 提交 | **提交即启动 rebuttal 预案** | 列出每条可能被攻击的弱点+对应证据/补充实验，提前备好 |

## 差异规则

- 审稿人视角写作：每条 claim 落地到实验或引用，无证据的话删掉
- rebuttal 期短（常 5-7 天），算力与人力预留；补实验窗口在提交前就要心里有数
- 逐字核验引用：没读过原文的文献不进 related work
- 拒稿 = 免费审稿意见：每轮意见回写研究计划，改投下一档
- 双盲会议注意自查：致谢、仓库链接、数据里的水印都可能漏身份
