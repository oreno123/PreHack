# Flow · UC12 命题平台型

**判型特征**：指定平台/技术栈（鸿蒙、华为云、小程序、指定 SDK），技术合规计分，评委可能在目标环境复验。与 UC2 区别：平台本身是题目的一部分。

**核心律**：平台踩坑侦察前置——把平台最恶的坑在阶段 2 全踩一遍，别到阶段 4 才发现做不了。

## 阶段权重

| 阶段 | 权重 | 裁剪规则 |
|---|---|---|
| 0 情报 | **加重** | 必须用的 SDK/版本/认证方式全抄；**开发者账号、签名证书、上架审核的申请周期写进日历倒排** |
| 1 选题 | 正常 | 在命题范围内选切口，差异化打评分表里"创新"那栏 |
| 2 spike | **加重=平台侦察** | 目标平台跑通最小 demo 全链路（部署/签名/权限/真机），产出坑清单 |
| 3 设计 | 按平台能力设计 | 设计前先确认平台做得到（Web 里的常识在目标平台可能是坑） |
| 4 构建 | 严格执行平台规范 | 真机/目标环境验证，模拟器通过不算通过 |
| 5 交付物 | 正常 | 截图/录屏全部用目标平台真机画面 |
| 6 提交 | 按平台要求 | 安装包/云链接按公告，评委会复验所以演示必须部署在目标平台跑 |

## 差异规则

- 平台特有坑（打包、组件限制、 WebView 行为差异）踩过后**留档成文档**，下次直接查——这是本型最大的复利
- 官方文档直接抓文本版（URL 加 `.md` 等技巧），离线可查
- 账号/证书类等待期是隐形 deadline，第一天就发起申请
- 云资源类平台注意免费额度与到期时间，演示当天资源失效=灾难
- 平台评分常有"技术合规"硬项，别全押创意

## 工具

- components: `cn-dev-cheatsheets`（部署/验收配方）
- skills: 平台相关 skills 按需
