# Flow · UC5 调研报告

**判型特征**：调研/案例/分析类比赛，交付 = 报告 + 图表 + 附录，无（或弱）代码交付。

**核心律**：skills 主力，数据纪律是底线——不假数、来源 URL、时效标注，缺一不可。

## 阶段权重

| 阶段 | 权重 | 裁剪规则 |
|---|---|---|
| 0 情报 | 正常 | 加重：题目要求、评审偏好、往届获奖报告的形态（页数/图表密度/附录规模） |
| 1 选题 | 正常 | 切口要窄：一页能讲清的研究问题 |
| 2 spike | **主战场** | 数据可得性验证 = 核心工作：每个数据源先探一条真实记录，拿不到的换题 |
| 3 设计 | 弱化 | 换成"报告骨架"：结论树 + 图表清单（每张图有数据来源标注位） |
| 4 构建 | → 分析 | 数据清洗 + 建模 + 出图；结论先行结构 |
| 5 交付物 | 正常 | 报告排版 + 附录（原始数据/来源清单/口径说明） |
| 6 提交 | 正常 | PDF 变换检查（字体/公式/页码），格式逐字核 |

## 差异规则（数据纪律红线）

- 结论先行：每页第一行就是这页的结论
- 不假数：没有的数据写"未获取"，不编；区间不假精确
- 每个数字带来源 URL + 时效标注；同口径对比，不跨数据集
- 多轮审查：数据、口径、表述至少各审一轮，单轮必漏
- 图表配色走等明度体系，表格缺格用口语问句标注
