# Flow · UC6 数模 72h

**判型特征**：72-120h 限时、题目三选一、交付 = 建模论文 PDF + 支撑代码，摘要页决定初筛生死。

**核心律**：论文骨架先行，摘要最后写但最重要；建模/编程/写作三线并行不停工。

## 时间轴（以 72h 计）

| 阶段 | 预算 | 裁剪规则 |
|---|---|---|
| 0 情报 | **赛前完成** | 模板、模型卡片、论文骨架、代码环境全部赛前备好；开赛后只读题 |
| 1 选题 | 4-6h | 三题各 2h 快评（数据可得性/模型套路熟悉度/工作量），选一即锁定 |
| 2 spike | 4h | 数据预处理 + 主模型一次粗跑通，跑不通换思路不换题 |
| 3 设计 | 3h | 换成**论文骨架**：问题重述/假设/符号说明/模型/求解/检验/评价，逐节占位 |
| 4 构建 | ~40h | 建模求解迭代：求解 → 验证 → 灵敏度分析，逐问推进不死磕 |
| 5 交付物 | 12h | 论文成文 + 图表规范 + 代码附录；**摘要最后 3 小时专职打磨** |
| 6 提交 | 2h | PDF 格式 / 承诺书 / 命名 / 查重自查 |

## 差异规则

- 摘要 = 评委唯一必读页：问题-方法-结果-结论四要素+具体数字，一页写满
- 三问结构：论文各节标题对齐题目小问，评委按问找答案
- 灵敏度分析必有一节，没有=方法不稳健直接扣档
- 分工三线：建模手/程序手/写作手，写作手第一天就开始填骨架
- 第 60h 未完成全部求解 = 砍问题深度，保论文完整度
