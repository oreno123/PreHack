# Flow · UC11 数据竞赛型

**判型特征**：leaderboard 打榜、线上测试集评分、提交次数限量、指标排名定奖。与 UC2 区别：没有"作品"，只有分数。

**核心律**：线上线下分布对齐是第一生命线；提交配额是稀缺资源，每次提交都要买到信息。

## 阶段权重

| 阶段 | 权重 | 裁剪规则 |
|---|---|---|
| 0 情报 | 正常+ | 评估指标/提交频率/榜单可见性/组队与外部数据规则逐条抄 |
| 1 选题 | 跳过 | 题目已定 |
| 2 spike | **加重=数据理解** | EDA+分布探查+线上线下一致性检查；baseline 粗跑通拿到首个分数 |
| 3 设计 | 换成验证策略 | 切分方案（时间切/分组切）定死，防泄漏；本地 CV 与线上分差建立映射 |
| 4 构建 | **主战场** | 特征/模型迭代循环；每次实验 seed 固定+配置留档可复现 |
| 5 交付物 | 弱化 | 通常只需方案文档，边打边写 |
| 6 提交 | **配额管理** | 每次提交前自问"这次提交买到什么信息"；末期防过拟合 public 榜 |

## 差异规则

- **只信本地 CV**：public 榜名次只当参考，private 翻转是常态，模型选择以本地 CV 为准
- 提交格式在第一次提交就验掉（又是格式坑，第一次提交名额就是用来买这个的）
- 验证与榜分背离 = 先查切分泄漏，再怀疑分布漂移
- ensemble 有边际但别早做：单模型没榨干前不碰
- 数据集本身先验真：来历不明/质量存疑的数据集（拼凑、造假、口径混乱）宁可弃赛
- 打榜末期策略：最后 1-2 次提交留给自己最有把握的两个模型
