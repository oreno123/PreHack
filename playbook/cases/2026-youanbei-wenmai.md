## 核心教训（正面：审查方法论的富矿）

1. **zip 审查必须内容级，文件名扫描不够**：首版只扫文件名，内容级 grep 抓出明文 API key ×3 + 平台 token ×5 + 真名 + 内部包名，两轮共 34 处替换为占位符。正则清单：`sk-/[A-Za-z0-9]{20,}`、token hex、真名、`@邮箱`、`github.com/ID`、LICENSE/egg-info（隐形雷区）
2. **元数据要扫三层**：模板自带 author=赛方人员名（模板污染）、lastModifiedBy、图片 EXIF——统一改成队名
3. **跨赛复用 deck 整包重扫**：拿获奖比赛的 PPT 换装参赛，原稿里还有真名、队友名、旧赛页脚——Ctrl+H 洗完正文，元数据和残留页脚靠脚本收尾
4. **占位符要通配抓变体**："待拍照/待截图/待替换"是一族；终审必须通读全文一次，碎片 grep 会漏措辞级问题（占位变体/内部术语泄入/事实矛盾）
5. **真实性表述以事实为准**："真机验证"未做就写"入围决赛"；游客入口实测不存在就把测试说明改成直链+登录说明——材料里的每个"已验证"都要有对应动作
6. **数字口径跨材料拉平**：毛利率/系列数在方案、PPT、测试说明三处必须一致；真相源是代码（数 `id: "`），不是任何一份文档
7. **视频编码是提交格式坑**：H.265 一律转 H.264（表单常只收后者）；转码后元数据只应剩 encoder
8. **截止期教训**："晚截止"是材料口径，报名/提交入口可能更早关——多赛并行时入口状态当天一早确认
